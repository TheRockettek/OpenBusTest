System Variables

Timegap
Duration of the previous frame in seconds.

GetTime
How long OMSI has been running in seconds.

NoSound
0: Sound enabled; 1: Sound disabled.

Pause
0: Unpaused; 1: Paused.

(If this game is paused then OMSI isn't executing script frames, so when will this ever be true?)

Time
Time of day (seconds since midnight).

Day, Month & Year
Calendar date.

DayOfYear
1 on 1st January.

A couple of default sound cubes use this to mute themselves at certain times of year.

mouse_x & mouse_y
Mouse drag deltas in pixels for script interactions. `mouse_x` is positive to
the right; `mouse_y` is positive down, matching the screen-space convention
used by the renderer and authored OMSI drag handlers.
They are zero outside a drag callback; a stationary hold still invokes _drag
with zero deltas. Absolute cursor position is available separately through
the OpenBus mouse_cursor_x and mouse_cursor_y variables.

PrecipType
What kind of water is falling from the sky?

1 = No precipitation;
2 = Rain;
3 = Snow.
The default buses use this to ensure the sound of raindrops hitting the roof only plays when it is raining.

PrecipRate
Rate of precipitation; varies between 0 (no precipitation) to 1 (maximum precipitation). The rate of raindrop accumulation on the windows will depend on this variable.

coll_pos_x, coll_pos_y & coll_pos_z
Location of collision (metres, relative to vehicle origin) in the frame where the system trigger collision is triggered.

coll_energy
Collision "energy" (newton‐metres‽) in the frame where the system trigger collision is triggered.

Weather_Temperature
Ambient temperature (℃) of the environment.

Weather_AbsHum
Absolute Humidity (gm−3) of the environment.

AutoClutch
0: Automatic Clutch setting disabled, 1: enabled.

wearlifespan
Not used, see the predefined local variable of the same name.

SunAlt
Sun elevation (° above horizon). See also: Envir_Brightness

System Triggers

collision
int_haltewunsch
railbond_#
ai_scheduled_settarget
ai_scheduled_setbusstop
malfunction_gettime
malfunction_reset
veh_tank

`ScriptRuntime::invokeSystemTrigger` dispatches vehicle and human triggers to
their `trigger_<name>` entry points and returns the top numeric stack value.
Chassis contacts populate `coll_pos_x/y/z` and `coll_energy` before dispatching
`collision`; the reported energy is the chassis's normal translational impact
energy. Scheduled map AI buses dispatch `ai_scheduled_settarget` when loaded or
a trip begins, and `ai_scheduled_setbusstop` when their next stop changes.

OpenBus currently has no event source for `int_haltewunsch`, `railbond_#`,
`malfunction_gettime`, `malfunction_reset`, or `veh_tank`; those triggers can
still be invoked explicitly, but passenger stop requests, rail joints, repair,
and refueling behavior are not simulated.

OpenBus Implementation Notes: Remaining Work

The inventories above describe OMSI script names and signatures. Recognition of a
name does not necessarily mean that its OMSI behavior is implemented. The notes
below distinguish host-updated values and implemented macros from names that
currently return placeholder values.

System Variables

The simulation clock variables (Time, Day, Month, Year, DayOfYear), Timegap,
GetTime, mouse_x, and mouse_y are updated by the runtime. mouse_x and mouse_y
are handler-scoped drag deltas; mouse_cursor_x and mouse_cursor_y are OpenBus
extensions containing cursor coordinates.
DayOfYear uses the one-based OMSI convention (1 on January 1). This replaces
the previous OpenBus zero-based behavior.

PrecipType uses OMSI values (1 = none, 2 = rain, 3 = snow); OpenBus maps its
internal weather enum to these values for scripts and maps back for rendering.
PrecipRate is initialized from the selected weather. Both share the values used
by precipitation rendering, and their predefined vehicle-local counterparts
are refreshed from the system values before initialization and each active
frame. NoSound is 0 when an OpenAL
context was created and 1 when audio initialization failed; it is refreshed
each frame. It does not report individual clip failures or device loss.

`Weather_Temperature` and `Weather_AbsHum` are set from the host weather
configuration (`OPENBUS_WEATHER_TEMPERATURE` in degrees Celsius and
`OPENBUS_WEATHER_ABSHUM` in g/m3; defaults are 20 and 10). These values are
published together with precipitation before scripts run.

`AutoClutch` reflects the opt-in `OPENBUS_AUTO_CLUTCH` host setting (0 by
default, 1 when enabled). It is reported to scripts; it does not enable
automatic clutch behavior in the drivetrain.

`SunAlt` reflects the optional `OPENBUS_SUN_ALTITUDE` setting in degrees,
defaulting to 60 and restricted to -90 through 90. OpenBus does not yet
calculate sun position from simulation time and map location.

`Pause` is 1 while the simulation is paused with `P`, and 0 after resuming with
`P`. Physics, traffic, passenger service, the simulation clock, and script
frames and vehicle key/mouse script events stop while paused; rendering, window
input, and free-camera movement continue. An active mouse interaction receives
its release event, and held vehicle key bindings receive their release events,
as pause begins so script controls can reset.

Predefined Local Variables

The physics runtime refreshes wheel rotation, wheel speed, suspension, steering,
`Brakeforce`, and per-wheel `Axle_Brakeforce` from the active ODE simulation.
`Velocity` is derived from driven-wheel rotation, while `Velocity_Ground` uses
chassis speed and `n_Wheel` reports the driven-wheel RPM average. The odometer
counters are updated from vehicle displacement, passenger counts from the live
passenger service, and precipitation from the selected environment.

Scheduled map AI buses publish `SetLineTo`, `AI_target_index`,
`target_index_int`, `act_busstop`, and `schedule_active`. They set
`AI_Scheduled_AtStation` to 1 on arrival, then to -1 when passenger service
finishes; the bus remains stopped until its script sets the variable to 0.
The selected depot name is also exposed as `yard`. `coll_pos_x/y/z` and
`coll_energy` are populated before the `collision` trigger runs.

Other predefined names are declared with safe defaults or are script-owned;
OpenBus does not currently simulate fuel level, maintenance condition, road
wetness, environmental brightness, door request/open state, train coupling or
rail telemetry, seat adjustment, force feedback, cabin-air or exterior dirt
simulation, and scenery night-use/approach state. Scenery traffic-light phase
is populated when its parent signal sequence is available.

Macros With Runtime Behavior

The script-texture macros (STNewTex, STLock, STUnlock, STFilter, STSetColor,
STDrawPixel, STDrawRect, STTextOut, STReadPixel, STCopyColor, STLoadTex,
STGetR/G/B/A, GetFontIndex, and TextLength) have runtime implementations.
NrSpecRandom is implemented as a seeded pseudo-random value; OMSI algorithm
parity is not verified. Finite seeds are truncated toward zero and must fit an
unsigned integer. Invalid seeds return zero and log one warning per runtime.

GetTicketName and GetTicketValue read indexed ticket data from local or shared
script state. The map loader publishes the active ticket pack there.
GiveChangeCoin reads the indexed denomination from local or shared script state
and updates OpenBus cash-dispensing state. These are script-state integrations,
not a complete OMSI ticket machine or fare system. GetHumanCountOnPathLink and
GetHumanCountOnSeat read indexed counts from local script state; vehicle seat
counts are refreshed from the live passenger service. During simulated
boarding/alighting, `GetHumanCountOnPathLink` reports the active passenger on
the corresponding authored cabin `[pathlink]`; it returns zero outside cabin
links or when no cabin path is available. Occupancy follows passenger-service
progress rather than camera visibility. Link indexes are zero-based in
`[pathlink]` declaration order. Scenery/world path-link occupancy is not
simulated.

Scheduled map AI buses retain their `.ttl` departure profile selections and
the `.ttp` stop timing profile. Their line, destination, stop names, and
arrival/departure times are published before scripts initialize. `GetTTDelay`
returns the signed difference in seconds between simulation time and the
timetable's expected time at the AI bus's current route position. `GetTTTerminusIndex` returns the zero-based index of the last mapped stop on
the AI bus's route, or `-1` when the route has no mapped stops.

The vehicle route and depot macros read the selected `hof_file` from the loaded
HOF data: termini come from `[addterminus]`/`[addterminus_list]`, bus stops from
`[addbusstop]`/`[addbusstop_list]`, routes and their stop lists from
`[infosystem_trip]`/`[infosystem_busstop_list]`, and depot strings from
`[global_strings]`. Route indexes follow HOF trip order. `GetRouteTerminusIndex`
returns the trip's terminus-index field; `GetBusstopCount` and
`GetRouteBusstopIdent` use that trip's stop list. `GetBusstopIndex` searches
the HOF bus-stop list by identifier, ignoring case and surrounding whitespace.
Without a selected, readable HOF file, these macros return the documented
missing/empty result and warn once per macro.

`NrSpecRandom` combines the integer seed with a stable hash of the vehicle's
`number`, so equal fleet numbers and seeds produce repeatable values while
different fleet numbers can vary. The generator is OpenBus-specific; parity
with OMSI's exact random sequence is not verified.

`GetHeightAbovePoint` transforms the supplied vehicle-local point through the
live chassis pose and raycasts downward against the active static collision
world, including streamed map geometry. It returns zero and logs once when no
ground surface is available.

Macros whose host data source is not currently exposed are:

- `GetArrBusLine`, `GetArrBusTerminus`, and `GetArrBusTimeDiff`: scenery script
 runtimes do not currently receive parent bus-stop arrival queues.

These macros consume their documented operands and return an empty string or
zero when their host data source is unavailable. The runtime logs that missing
provider once per macro.

Both backends preserve the top string when `(S.$...)` stores it, matching the
stack behavior of numeric stores; a cross-backend probe covers chained stores.
System-macro availability is also restricted by object kind in both backends.
Exact OMSI parity for string-store stack behavior and out-of-kind macro calls
has not been independently verified.
