System Variables

Timegap
Duration of the previous frame in seconds.

GetTime
How long OMSI has been running in seconds.

NoSound
0: Sound enabled; 1: Sound disabled.

Pause
0: Unpaused; 1: Paused.

(If this game is paused then OMSI isn't executing script frames, so when will this ever be true?)

Time
Time of day (seconds since midnight).

Day, Month & Year
Calendar date.

DayOfYear
1 on 1st January.

A couple of default sound cubes use this to mute themselves at certain times of year.

mouse_x & mouse_y
Mouse drag deltas in pixels for script interactions. `mouse_x` is positive to
the right; `mouse_y` is positive down, matching the screen-space convention
used by the renderer and authored OMSI drag handlers.
They are zero outside a drag callback; a stationary hold still invokes _drag
with zero deltas. Absolute cursor position is available separately through
the OpenBus mouse_cursor_x and mouse_cursor_y variables.

PrecipType
What kind of water is falling from the sky?

0 = No precipitation;
1 = Rain;
2 = Snow.
The default buses use this to ensure the sound of raindrops hitting the roof only plays when it is raining.

PrecipRate
Rate of precipitation; varies between 0 (no precipitation) to 1 (maximum precipitation). The rate of raindrop accumulation on the windows will depend on this variable.

coll_pos_x, coll_pos_y & coll_pos_z
Location of collision (metres, relative to vehicle origin) in the frame where the system trigger collision is triggered.

coll_energy
Collision "energy" (newton‐metres‽) in the frame where the system trigger collision is triggered.

Weather_Temperature
Ambient temperature (℃) of the environment.

Weather_AbsHum
Absolute Humidity (gm−3) of the environment.

AutoClutch
0: Automatic Clutch setting disabled, 1: enabled.

wearlifespan
Not used, see the predefined local variable of the same name.

SunAlt
Sun elevation (° above horizon). See also: Envir_Brightness

The timetable numeric macros are implemented for scheduled AI buses.
`GetTTBusstopCount` and `GetTTBusstopIndex` expose the retained route's stop
count and current stop. `GetTTTerminusIndex` returns the zero-based index of
the last mapped stop on the route, or `-1` when no stops are mapped.
`GetTTDelay` reports signed seconds against the selected timetable profile.
`GetTTBusstopArr` and `GetTTBusstopDep` consume a route stop index and return
that stop's profile time, or zero when no profile time is available.

Scheduled map AI buses receive the matched timetable line, destination, stop
names, and times before their scripts initialize. `GetTTLineString` returns the
timetable line name. `GetTTBusstopName` consumes a route stop index and returns
the corresponding stop name; the destination name is retained in the
`tt_busstop_name` script variable.

OpenBus Implementation Notes: Remaining Work

The inventories above describe OMSI script names and signatures. Recognition of a
name does not necessarily mean that its OMSI behavior is implemented. The notes
below distinguish host-updated values and implemented macros from names that
currently return placeholder values.

System Variables

The simulation clock variables (Time, Day, Month, Year, DayOfYear), Timegap,
GetTime, mouse_x, and mouse_y are updated by the runtime. mouse_x and mouse_y
are handler-scoped drag deltas; mouse_cursor_x and mouse_cursor_y are OpenBus
extensions containing cursor coordinates.
DayOfYear uses the one-based OMSI convention (1 on January 1). This replaces
the previous OpenBus zero-based behavior.

PrecipType and PrecipRate are initialized from the selected weather and share
the values used by precipitation rendering. Their predefined vehicle-local
counterparts are refreshed from the system values before initialization and
each active frame. NoSound is 0 when an OpenAL
context was created and 1 when audio initialization failed; it is refreshed
each frame. It does not report individual clip failures or device loss.

The following documented system variables are declared, but do not currently
receive live host values: Pause, coll_pos_x, coll_pos_y, coll_pos_z, coll_energy,
Weather_Temperature, Weather_AbsHum, AutoClutch, and SunAlt. Unless a script
sets them, their initialized defaults are returned. Collision values are not
populated when a collision trigger runs.

wearlifespan is initialized as a system variable, but the documented behavior
uses the predefined local variable of the same name instead.

Macros With Runtime Behavior

The script-texture macros (STNewTex, STLock, STUnlock, STFilter, STSetColor,
STDrawPixel, STDrawRect, STTextOut, STReadPixel, STCopyColor, STLoadTex,
STGetR/G/B/A, GetFontIndex, and TextLength) have runtime implementations.
NrSpecRandom is implemented as a seeded pseudo-random value; OMSI algorithm
parity is not verified. Finite seeds are truncated toward zero and must fit an
unsigned integer. Invalid seeds return zero and log one warning per runtime.

GetTicketName and GetTicketValue read indexed ticket data from local or shared
script state. GiveChangeCoin reads the indexed coin value and updates OpenBus
cash-dispensing state. These are script-state integrations, not a complete
OMSI ticket machine or fare system. GetHumanCountOnPathLink and
GetHumanCountOnSeat read indexed counts from local script state; they are not
backed by a complete passenger/path-link simulation.

Scheduled map AI buses retain their `.ttl` departure profile selections and
the `.ttp` stop timing profile. Their line, destination, stop names, and
arrival/departure times are published before scripts initialize. `GetTTDelay`
returns the signed difference in seconds between simulation time and the
timetable's expected time at the AI bus's current route position. `GetTTTerminusIndex`
returns the zero-based index of the last mapped stop on the AI bus's route, or `-1`
when the route has no mapped stops.

Macros Still Returning Placeholder Results

Vehicle route, terminus, and bus-stop lookup:
GetTerminusIndex, GetTerminusCode, GetTerminusString, GetBusstopIndex,
GetBusstopString, GetRouteIndex, GetRouteTerminusIndex, GetBusstopCount, and
GetRouteBusstopIdent.

Other vehicle queries:
GetHeightAbovePoint and GetDepotStringGlobal.

Scenery arrival queries:
GetArrBusLine, GetArrBusTerminus, and GetArrBusTimeDiff.

The remaining macros above are recognized by the script runtime, but their
query results are placeholders: empty strings, zero, or -1. A complete
implementation requires the corresponding route/depot, geometry, or arrival
data to be made available to scripts. These placeholders log a warning once
per runtime and macro when invoked.

Backend compatibility limitation: native string stores currently consume the
top string, while converted Lua string stores leave it on the stack. Native
system-macro dispatch also does not enforce the object-kind availability
checks used when registering Lua macros. Native OMSI behavior for string stores
and out-of-kind macro calls has not been verified.
